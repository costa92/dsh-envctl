## 必须补（2026-09-25 已落地）

下列五项已实现并用测试钉死：读 `package.json` + bundles、按依赖 spec 分类、外部 symlink 不读元数据、CLI 读 `DSH_HOME`、相对 `--dsh-home` 转绝对。证据：`tests/inventory/inventory.spec.ts`、`tests/cli/home.spec.ts`、`tests/environment/paths.spec.ts`。

### 1. 盘点读了假文件，没读 DSH Profile（已修）

真实 Web Profile（本机核实）：

```text
~/.dsh/profiles/web/
  package.json      # name/private/dependencies + dsh.profile.bundles
  cordis.patch.yml
  pnpm-workspace.yaml
  node_modules/     # 当前为空
```

没有 `profile.json`。

实现读 `profiles/<name>/profile.json` 的 `plugins` 表，再扫整个 `node_modules`。

后果：对本机真实 web Profile 执行 capture，官方 bundle `@deepseek-ai/dsh-base`、`@deepseek-ai/dsh-web-app` 不可见；装了社区插件时会把传递依赖也当成插件。

应改为：只读该 Profile 的 `package.json`。`dependencies` / `optionalDependencies` 是树外插件；`dsh.profile.bundles` 是启用选择。内置 bundle 不在 dependencies 里，应单独列为 in-box，不得当成 npm 包去装。

### 2. 用「是不是 symlink」判断来源，pnpm 会全判成 local-link（已修）

pnpm 把直接依赖链到 `node_modules/.pnpm/...`，真实 npm 包几乎都是 symlink。`classifySource` 在 `isSymlink` 时直接返回 `local-link`。

测试能过，是因为 fixture 把包写成了普通目录。

应改为：以来源 **spec 字符串** 分类（`link:` / `file:` / git URL / 版本号），symlink 只用于越权检测。

### 3. 外部 symlink 仍跟随读取元数据（已修）

计划：realpath 证明仍在 Profile 内，否则只报 `external-metadata`，禁止越出读取。

实现：外部 symlink 仍 `readFileSync(pkgPath/package.json)`，默认跟随链接。审查重点未落地。

### 4. CLI 未使用 `DSH_HOME`（已修）

路径函数支持 `envDshHome`，测试也覆盖了优先级。`runCli` 只传 `--dsh-home`，从不读 `process.env.DSH_HOME`。README 写了第二优先级，实际无效，无 flag 时永远落 `~/.dsh`。

### 5. `--dsh-home` 拒绝相对路径（已修）

实现要求绝对路径。计划冒烟命令是 `node bin/dshenv.js capture --dsh-home tests/fixtures/dsh-home`，当前会失败（已复现：`CLI dsh-home must be an absolute path`）。`--output` 却会相对 cwd 解析。应统一：相对路径先相对 cwd 再规范化。
